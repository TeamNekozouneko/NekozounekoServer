# NekozounekoServer
IssuesタブからNekozouneko Serverの報告されたバグと進捗が確認できます。  
GitHubアカウントをお持ちの方は、テンプレートに従ってご投稿いただいてもご対応させていただきます。  
DiscordのサポートセンターやTicketでご報告いただいたバグもIssuesに移動してご対応いたします。  
## バグの対応原則
### 原因は無限にあります
「サーバーに入れない」その一言で原因のパターンは、玉ねぎの皮を剥くようなものです。  
本質なる原因はその中核にあり、何層もの派生原因を生み出します。  
私たちが表面に見えるものだけで、その原因を探ることは不可能です。  
その表面上の「サーバーに入れない」だけを伝えるのではなく、
* いつ頃から入れないのか
* 入れない時はどんな画面が出るのか
* 端末は何を使っているのか
* どのように入ろうとしてダメだったのか
* ネット回線はWi-Fiもしくは4G/5Gのどちらか

etc... できる限りの情報をすべて伝えてください。
### バグはすべて治せません
サーバーに入ったその1秒の瞬間に、数万人以上のエンジニアの苦労があります。  
どんなサービスでも、時のように無数のプログラムが裏では絶え間なく動いています。  
とても素晴らしい記事を見つけたため、余裕のある方は一度ご覧になると良いかもしれません。  
[システム開発からバグがなくなることはない | 米村 歩](https://axia.co.jp/2021-02-22)
### Java版の動作は変えられません
通常、統合版のプレイヤーがJava版のサーバーに入れるというのは異常なことです。  
翻訳機のようなもの使って統合版の通信をJava版の通信に無理やり変換することで実現できています。  
そのため、サーバー側の動作はすべてJava版を優先します。
### 統合版は制限があります
翻訳機すなわちGeyserは、Java版と統合版の仕様の違いにより、治すことのできない動作があります。  
これは統合版とJava版が違うシステムである以上、どうしようもできません。  
直せないバグは、GeyserMC公式がサイトにて公表しています。  
[Current Limitation | GeyserMC](https://geysermc.org/wiki/geyser/current-limitations/)
### エンジニアに「ありがとう」を
皆さんは、バグが起きたとき「ここの動作をこうするだけじゃん」と疑問になることがありませんか。  
そうです、そこの動作をそうするだけです。じゃあプログラムを渡すのでその部分を直してみてください...  
皆さんが目にみえるものとは乖離して、実際にはすべてプログラムという英字の並びを見て直します。  
そんなグラフィカルなゲームを遊ぶような楽しい感覚は、ほとんどありません。  
直してくれたときの「ありがとう」その一言を全国、全世界のエンジニアに届けましょう。
